# Project Context Reference Implementation

This directory is a schema validation example, not a template for copying project facts into real projects.

Its purpose is to demonstrate how an AI-maintained Project Context can represent a realistic software project while remaining readable, traceable, and updateable.

## Rules

- Example data is intentionally fictional.
- Every domain uses the v1 common schema and its domain schema.
- User decisions are explicitly protected.
- AI inference is never presented as confirmed fact.
- `ai-handoff` is a derived snapshot and is not the source of truth.
- Work states remain separate: completed, in-progress, next, backlog, blocked.

## Example Project

**Project:** Acme Order Management API

A small fictional backend service used only to exercise the Blueprint. The example is deliberately generic so it does not imply a preferred implementation technology.
