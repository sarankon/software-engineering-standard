# Changelog

## 1.2.0 — Project Context Completion Gate

- Strengthened normal development completion with a mandatory Context Reconciliation Result.
- Required explicit classification of Project Context impact as `REQUIRED` or `NOT_REQUIRED`.
- Required affected domains, work state, updated Context files, AI Handoff status, and evidence-based reason before completion.
- Kept Project Context Blueprint and Schema versions unchanged because their data structures were not modified.

## 1.1.0 — Project Context Maintenance

- Added the Project Context Maintenance Procedure for normal development work.
- Made Project Context impact assessment and reconciliation part of the development completion lifecycle.
- Added requirements for updating affected canonical domains, work-management states, and AI Handoff.
- Updated the AI Bootstrap contract and AI entry-point guidance so implementation completion does not bypass Project Context maintenance.
- Added and updated the migration guidance from Framework 1.0.0 to 1.1.0.
- Advanced the Foundation Standard to 0.2.0 for the AI entry-point requirement.

## 1.0.0 — Foundation

- Initialized Software Engineering Standard repository.
- Established top-level areas for standards, AI development, project-context blueprints, and migrations.
