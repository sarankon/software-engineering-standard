Software Engineering Standard — Foundation

Draft · ภาษาไทยสำหรับ Review

มาตรฐานพื้นฐานของโครงการ 7 เรื่อง ตั้งแต่โครงสร้าง repository configuration environment dependencies documentation และ AI entry point

1. Project Structure

โครงสร้างต้องทำให้ความรับผิดชอบชัด ค้นหาได้ง่าย สม่ำเสมอ และเหมาะกับเทคโนโลยีของโครงการ

MUST: สะท้อนความรับผิดชอบที่มีความหมาย และทำให้มนุษย์กับ AI ค้นหาองค์ประกอบสำคัญได้
MUST NOT: เพิ่มโครงสร้างหรือ abstraction โดยไม่มีประโยชน์ที่ชัดเจน

ไม่บังคับ physical directory layout และ Project Context ต้องแยกจาก source/artifacts อย่างเหมาะสม

2. Repository

Repository ต้องเป็นแหล่งเก็บ source และประวัติการเปลี่ยนแปลงที่ตรวจสอบย้อนกลับได้

MUST: ใช้ source control มี default branch ชัดเจน commit ต้องมีความหมาย และรักษา repository hygiene
MUST NOT: เก็บ secret ที่ใช้งานได้ และเมื่อ secret รั่วต้องมี remediation

ไม่บังคับ Git Flow, trunk-based, PR/MR หรือ workflow ใดโดยเฉพาะ

3. Configuration

Configuration ต้องมี classification, ownership และวิธีจัดการชัดเจน ค่าที่เปลี่ยนตาม environment ควร externalize

MUST: แยก secret ออกจากค่าที่ไม่ลับ ใช้ safe defaults และ validate ค่าที่สำคัญ
MUST NOT: ฝัง secret หรือ environment-specific values ใน source โดยไม่จำเป็น

ไม่บังคับ format หรือ platform

4. Environment

แต่ละ environment ต้องมี purpose, ownership, lifecycle และ isolation ที่เข้าใจได้ ความแตกต่างต้อง intentional และ reproducible เท่าที่จำเป็น

MUST: ควบคุมข้อมูล การเข้าถึง ความปลอดภัย และ promotion/deployment ตามความเสี่ยง

ไม่กำหนดจำนวน/ชื่อ environment และไม่บังคับ CI/CD platform

5. Dependencies

Dependency ต้องถูกเลือก ประกาศ version และดูแลตลอด lifecycle

MUST: ระบุ direct dependency ชัด ควบคุม version และทำให้ reproduction ตรวจสอบได้
SHOULD: ทบทวน vulnerability, license/compliance, dependency ที่ล้าสมัยหรือไม่ใช้แล้ว และแยก direct/transitive

ไม่บังคับภาษา package manager registry หรือ tool

6. Documentation

Documentation เป็น engineering artifact ต้องมี owner, source of truth, discoverability และความถูกต้อง

MUST: เอกสารสำคัญต้องค้นหาได้ง่ายและปรับปรุงเมื่อระบบเปลี่ยน

ครอบคลุม architecture/design, operations, Project Context, AI-readable และ generated docs ตามความเหมาะสม โดยไม่บังคับ format/tooling

7. AI Entry Point

Repository ต้องมีจุดเริ่มต้นที่ authoritative สำหรับ AI

MUST: ระบุ loading order, การค้นหา Project Context, standards, authority/precedence และ scope

อาจใช้ AGENTS.md หรือเทียบเท่า แต่ SES ไม่บังคับชื่อไฟล์/platform จุด entry ต้องอ่านได้โดยมนุษย์และไม่ซ้ำกับ AI workflow ทั้งหมด
