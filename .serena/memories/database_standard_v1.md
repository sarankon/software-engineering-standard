Database Standard v1.0.0 has been approved and implemented under standards/data/. Locked decisions: Common Audit is the baseline for all mutable baseline/application tables; Audit Columns include is_active, is_active_before_delete, version, created_at/created_by/created_by_component, updated_at/updated_by/updated_by_component, deleted_at/deleted_by/deleted_by_component, audit_remark. created_by/updated_by/deleted_by use same type as users.id, FK to users.id, nullable. Component fields are varchar(255) and use stable logical component identifiers. is_active is business state; deleted_at is soft-delete state. Soft Delete sets is_active=false and stores previous state in is_active_before_delete; Restore restores that previous state. version starts at 1 and increments on every mutation including update, activate, deactivate, soft delete, restore. Activity Logs are mandatory from project initialization, use a dedicated append-only model rather than Common Audit, and must not contain sensitive data. Identity baseline includes Users, Organizations, User Organizations, Roles, User Roles, Permissions, Role Permissions, Groups, User Groups, Role Groups. Roles are Organization-scoped; role names are unique within organization. Groups belong to Organizations. Configuration baseline includes Definitions and Values with APPLICATION/ORGANIZATION/USER scopes. API Keys may have nullable expires_at; cryptographically secure secret >=128-bit; secret is shown once and never stored; prefix + key_hash are stored; lifecycle includes last_used_at/revoked_at/revoked_by. Baseline tables are provisioned for every application from initialization even if unused. Standard is technology-neutral; implementation technology belongs in Project Context.
