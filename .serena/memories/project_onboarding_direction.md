Project Onboarding is the next implementation stage after Project Context, Project Standard Profile, and Standard Assessment. It should connect the framework into an AI-led workflow for both new and existing repositories: Prompt → read repository source/config/project-owned docs (never Git history/commit/diff/branch/tag/blame) → reconstruct/update Project Context → determine/adopt Project Standard Profile → run Standard Assessment → report findings/evidence/confidence → propose changes → wait for explicit user decision → apply approved changes → validate. Existing project onboarding must be idempotent/update-friendly and preserve project-owned knowledge rather than blindly overwrite it. Recommended project-owned locations remain `.project-context/`, `.project-context/standards/profile.md`, and `.project-context/standards/assessments/`. AI is primary reader/writer; user is the decision/authorization boundary. Before implementing this stage, commit this direction memory first; after implementation, update memory with the result and commit again.
