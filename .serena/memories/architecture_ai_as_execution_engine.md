Architecture decision (2026-09-03): AI is the Framework execution engine. There is no separate Automated Bootstrap Runner or Framework Runtime Runner in target-project architecture. AI directly performs install, upgrade, migration, validation, and recording according to authoritative procedures, approval/state rules, and runtime validation policy. User remains the decision/authorization boundary: AI explains findings and proposals and waits for explicit approval before material changes. Test-only runners/simulators remain allowed only as Framework testing tools and are not target-project runtime components. Existing references to runners must be interpreted or updated consistently with this boundary. Runtime statuses are PASS, FAIL, BLOCKED, NOT_RUN; BLOCKED is not FAIL and must include reason/command. This decision supersedes earlier runner-based architecture suggestions.
