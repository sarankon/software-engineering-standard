Decision: Proceed with S1 Software Standard Schema before defining concrete standards (Security/UI/Database/etc.). Software Standard must support Version, Applicability, Project Override/Extension, Validation, and AI recommendation. Proposed standard structure separates Governance, Foundation Standards, Application Standards, UI Standards, and Engineering Practices. Requirement levels: mandatory, recommended, optional, forbidden. Project should consume a Global Standard via a Project Standard Profile with adopt/override/extend/exclude semantics; AI proposes compliance findings/actions and user decides before changes. Current workflow rule: before every next implementation step, update project memory and commit first, per user instruction. S1 designed in `schemas/software-standard/` and committed. `standard-schema.md` defines Standard collection metadata/governance, versioning, scope, applicability, validation, exceptions, and AI/user authorization boundary. `requirement-schema.md` defines individual requirement identity, levels, validation results, evidence, and AI interpretation rules. Existing `standards/SPECIFICATION.md` remains authoritative for the current rule corpus; S1 intentionally preserves existing `Status` and normative keyword conventions. Mapping between current rule keywords and canonical S1 levels is deferred to S2. Project Standard Profile schema is deferred to later phases.
