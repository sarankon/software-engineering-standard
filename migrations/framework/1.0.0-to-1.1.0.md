# Framework Migration Guide: 1.0.0 → 1.1.0

## Status

`released`

This guide defines the released migration path from Framework 1.0.0 to Framework 1.1.0.

## Scope

- Source Framework: `1.0.0`
- Target Framework: `1.1.0`

## Planned Changes

### MC-001 — Framework Update Metadata

- Classification: `compatible`
- Action: `adopt`
- Impact: low
- Transformation: update `.project-context/framework/version.yaml` to record the target Framework version and artifact versions actually adopted.

### MC-002 — Framework Update Schema

- Classification: `migration-required`
- Action: `migrate`
- Impact: medium
- Transformation: validate existing project-owned migration records against the target schema and transform fields only where required.
- Preservation: retain Migration IDs and Change Item IDs.

### MC-003 — Project Context

- Classification: `compatible`
- Action: `adopt`
- Impact: low
- Transformation: no domain data is rewritten unless a target Blueprint/Schema explicitly requires it. Revalidate version references and provenance.

### MC-004 — Project Context Maintenance Procedure

- Classification: `compatible`
- Action: `adopt`
- Impact: medium
- Transformation: install and make discoverable `ai_development/context-maintenance/project-context-maintenance.md` Procedure v1.0.0. Normal development tasks MUST assess and reconcile Project Context impact before completion.
- Compatibility: no Project Context schema migration is required.

### MC-005 — Foundation Standard

- Classification: `compatible`
- Action: `adopt`
- Impact: low
- Transformation: adopt Foundation Standard `SES-FND` v0.2.0. The AI entry point must make the Project Context Maintenance Procedure discoverable.
- Constraint: application source code is not modified as part of this Framework migration.

## Validation

1. Target Framework version is recorded exactly.
2. Migration Schema validation passes.
3. Existing Migration IDs are preserved.
4. Project Context remains structurally valid.
5. Project Standard Profile references exact adopted Standard versions, including Foundation Standard v0.2.0 when applicable.
6. Project Context Maintenance Procedure v1.0.0 is installed/discoverable.
7. Affected assessments are rerun when required.
8. AI Handoff remains consistent.
9. No unexpected application source/configuration changes occurred.

## Notes

Framework `1.1.0` is a released backward-compatible normative update. It adds mandatory Project Context completion maintenance without changing Project Context Blueprint/Schema versions.
