# Framework Migration: 1.1.0 to 1.2.0

## Scope

Framework 1.2.0 strengthens the normal development completion contract by adding a mandatory Project Context Completion Gate.

## Affected Artifacts

- Framework version: 1.1.0 → 1.2.0
- Project Context Maintenance Procedure: 1.0.0 → 1.1.0
- Project Context Blueprint: unchanged at 1.0.0
- Project Context Schema: unchanged at 1.0.0
- Software Standards: unchanged

## Change Classification

Compatible procedure enhancement. Existing Project Context records remain valid.

## Required Behavior

After implementation validation, AI MUST:

1. Assess Project Context impact.
2. Reconcile affected canonical domains.
3. Reconcile AI Handoff when continuity information changed.
4. Produce a Context Reconciliation Result before reporting completion.

The result MUST include:

- Project Context Impact: `REQUIRED` or `NOT_REQUIRED`
- Affected Domains
- Work State
- Context Files Updated
- AI Handoff Updated
- Evidence-based Reason

## Migration Actions

For an SES-enabled project:

- update the installed Framework version to 1.2.0;
- update the Project Context Maintenance Procedure to 1.1.0;
- preserve all existing Project Context records;
- do not rewrite the Blueprint or Schema when their structures are unchanged;
- apply the Completion Gate to the next normal development task.

## Validation

Confirm that:

- the installed framework version is 1.2.0;
- the maintenance procedure is 1.1.0;
- a feature task cannot be reported complete without a Context Reconciliation Result;
- `NOT_REQUIRED` includes a reason;
- `REQUIRED` identifies affected domains and updated files;
- Blueprint and Schema versions remain 1.0.0.

## Risks

The main risk is procedural non-compliance by an AI agent that reads only the old entry point or cached instructions. The target project's AI entry point should point to the installed maintenance procedure and active Framework version.

## Separation

This migration does not authorize application source-code, database, API, UI, or infrastructure changes.
